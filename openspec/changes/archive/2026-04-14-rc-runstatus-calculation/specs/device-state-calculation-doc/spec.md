# 设备状态计算规范

## 规范说明

本规范定义 MEOS 能源监控系统中设备运行状态（rcRunStatus）的计算逻辑和状态映射规则。

## 需求

### 需求 1：系统必须根据在线状态、设定值和实际运行状态计算设备运行状态

**优先级**：P0（核心功能）

**描述**：
系统必须通过触发公式（triggerFormula）动态计算设备的运行状态，计算公式必须考虑以下三个关键信息点：

- `onlineStatus`：设备在线状态（0=离线，1=在线）
- `equipSwitchSet` 或 `enableCtrl`：设备开关设定值（0=关闭，1=开启）
- `runStatus`：设备实际运行状态（0=停止，1=运行）

**计算逻辑**：

1. 如果设备离线（onlineStatus != 1），返回 -1（无效）
2. 如果设定值为 nil，返回实际运行状态（runStatus）
3. 如果设定值为 0（关闭）：
    - 实际状态为 0 或 nil → 返回 0（停止）
    - 实际状态为 1 → 返回 3（关闭中）
4. 如果设定值为 1（开启）：
    - 实际状态为 0 或 nil → 返回 2（开启中）
    - 实际状态为 1 → 返回 1（运行）

**验证方法**：

- 单元测试覆盖所有状态组合（参见状态映射真值表）
- 集成测试验证 MQTT 数据上报后的状态计算

### 需求 2：系统必须支持五种设备运行状态

**优先级**：P0

**描述**：
rcRunStatus 必须支持以下五种状态值：

| 状态值 | 状态名称 | 说明           |
|-----|------|--------------|
| -1  | 无效   | 设备离线或数据缺失    |
| 0   | 停止   | 设备已停止运行      |
| 1   | 运行   | 设备正常运行       |
| 2   | 开启中  | 设备正在启动（过渡状态） |
| 3   | 关闭中  | 设备正在停止（过渡状态） |

**验证方法**：

- 前端能够正确展示五种状态
- 状态值能够在数据库配置中正确定义

### 需求 3：系统必须支持配置驱动的状态计算

**优先级**：P0

**描述**：
状态计算逻辑必须通过数据库配置（info_code_config.extend_info.triggerFormulaInfo）定义，而不是硬编码在代码中。

配置必须包含：

- `triggerFormula`：计算表达式（Aviator 语法）
- `triggerInfoCode`：计算结果写入的信息点代码（rcRunStatus）
- `variables`：公式中使用的变量列表
- `sourceIotType`：数据源类型（0=控制指令，1=信息点表达式）

**验证方法**：

- 修改数据库配置后，系统能够使用新公式计算
- 无需重新部署代码即可更新计算逻辑

### 需求 4：系统必须实时计算并推送状态变化

**优先级**：P1

**描述**：
当设备上报 IoT 数据时，系统必须：

1. 检查是否存在 triggerFormulaInfo 配置
2. 如果有配置，立即执行公式计算
3. 将计算结果写入 Redis 缓存
4. 通过 WebSocket 推送到前端

**验证方法**：

- MQTT 数据上报后，rcRunStatus 在 100ms 内更新
- 前端能够实时接收到状态变化推送

### 需求 5：系统必须处理设备特殊逻辑

**优先级**：P1

**描述**：
对于特定设备类型，系统必须应用特殊的计算逻辑：

- **离心式冷水机组 (ACCCCC)**：
    - 单点控制模式：使用 equipSwitchSet 计算
    - 联动控制模式：使用 enableCtrl 计算

- **冷却塔控制单元 (ACCCSC)**：
    - 单点控制时不进行公式计算

- **空调换热器 (ACGEHE)**：
    - 单点控制时不进行公式计算

**验证方法**：

- 针对不同设备类型，验证使用正确的信息点进行计算
- 单点控制模式下，验证跳过公式计算

### 需求 6：系统必须防止并发计算冲突

**优先级**：P1

**描述**：
同一设备同一信息点的公式计算必须串行执行，使用 ReentrantLock 防止并发冲突。

**验证方法**：

- 并发上报同一设备的 IoT 数据时，不会导致计算错误
- 不会出现状态值不一致的情况

### 需求 7：系统必须支持边缘和云端两种部署模式

**优先级**：P2

**描述**：
状态计算逻辑在边缘部署（local）和 SaaS 云部署（saas）中必须保持一致：

- 使用相同的公式配置
- 使用相同的状态映射规则
- 差异仅在于执行时机（边缘实时 vs 云端批量）

**验证方法**：

- 边缘部署和云端部署产生相同的状态计算结果
- SQL 迁移脚本在两种部署中一致

## 状态映射真值表

| onlineStatus | equipSwitchSet | runStatus | **rcRunStatus** | 状态说明     |
|--------------|----------------|-----------|-----------------|----------|
| nil          | -              | -         | **-1**          | 无效（设备离线） |
| 0            | -              | -         | **-1**          | 无效（设备离线） |
| 1            | nil            | nil       | **-1**          | 无效（数据缺失） |
| 1            | nil            | 0         | **0**           | 停止       |
| 1            | nil            | 1         | **1**           | 运行       |
| 1            | 0              | nil       | **0**           | 停止       |
| 1            | 0              | 0         | **0**           | 停止       |
| 1            | 0              | 1         | **3**           | 关闭中      |
| 1            | 1              | nil       | **2**           | 开启中      |
| 1            | 1              | 0         | **2**           | 开启中      |
| 1            | 1              | 1         | **1**           | 运行       |

## 公式示例

### 使用 equipSwitchSet 的公式

```javascript
(onlineStatus == nil || onlineStatus != 1)
    ? -1
    : (equipSwitchSet == nil
        ? (runStatus == nil ? -1 : runStatus)
        : (equipSwitchSet == 0
            ? (runStatus == nil || runStatus == 0 ? 0 : 3)
            : (runStatus == nil || runStatus == 0 ? 2 : 1)))
```

### 使用 enableCtrl 的公式

```javascript
(onlineStatus == nil || onlineStatus != 1)
    ? -1
    : (enableCtrl == nil
        ? (runStatus == nil ? -1 : runStatus)
        : (enableCtrl == 0
            ? (runStatus == nil || runStatus == 0 ? 0 : 3)
            : (runStatus == nil || runStatus == 0 ? 2 : 1)))
```

## 非功能性需求

### 性能要求

- 公式计算延迟：< 100ms（边缘部署）
- 公式计算延迟：< 1s（云端部署）
- 支持每秒 1000+ 设备的并发状态计算

### 可用性要求

- 边缘部署支持离线运行
- 云端部署依赖网络连通性
- 缓存失效时能够降级处理

### 可维护性要求

- 公式配置必须支持版本管理
- 必须提供公式语法验证工具
- 必须记录公式执行的日志和异常

## 相关组件

- **ComputeIotDataHandler**：公式计算核心处理器
- **InfoCodeLinkControlHandler**：配置验证器
- **TriggerFormulaInfo**：公式配置实体
- **AviatorEvaluator**：表达式执行引擎
- **info_code_config**：数据库配置表
