# 安防动态查询与设备统计优化

## 目标与价值

在不缓存动态数据的前提下，降低安防通行空间、设备状态统计和异常状态对象范围的重复扫描与聚合耗时，使 HTTP 和 SSE 在下一次查询中反映最新规则、状态和异常事件。

## 背景与已确认事实

- 静态设备、空间和 EQUIPMENT_IN_SPACE 关系已由前置 security-static-cache 子任务提供；本任务只消费这些候选，不负责构建或刷新缓存。
- RunningMonitorSecurityStrategy#listAccessSpace 当前对每个返回空间再次扫描其设备关系，并在循环内逐空间写 INFO 日志。
- SecurityServiceImpl#getEquipmentTypeStatistics 当前对两组设备查询结果做全量设备 ID 的动态查询，并由两个异步任务直接写共享状态映射。
- SECURITY_EQUIPMENT_STATISTICS SSE 直接调用安防统计服务；SSE 事件类型、调度频率和响应结构必须保持兼容。

## 范围

### R1 通行空间规则聚合

- /security/listAccessSpace 继续实时获取 accessDemand 和 equipOnSet 规则。
- 使用静态设备候选和 EQUIPMENT_IN_SPACE 关系一次构造 spaceId -> {accessDemand,equipOnSet} 标志；两个标志均存在时保留空间。
- 规则分属不同门禁、重复关系、空关系、缺失规则和空动态值遵循旧接口语义；移除逐空间 INFO 日志，仅保留可聚合的耗时/异常日志。

### R2 设备统计动态聚合

- /security/equipment/statistics 及 SECURITY_EQUIPMENT_STATISTICS 只对前置静态候选过滤后的去重设备 ID 查询 armingStatus、onlineStatus、runStatus、deployWithdrawAlarmStatus 和异常事件。
- 保持门禁、入侵报警、普通摄像头、具备布撤防能力摄像头的分类、车库摄像头实时流协议过滤、离线/异常/布撤防/运行状态映射和零值展示语义。
- 动态 IoT 查询与异常事件查询各自产生局部结果，汇合后再计算统计 VO；不得并发写普通共享 Map。

### R3 安防异常状态对象聚合

- 安防异常状态 SSE 将空间与设备对象范围分别聚合，多设备类别 ID 一次去重后调用现有服务。
- 不修改通用 IoT 查询接口、实现、`batchQueryInfoCode`、`rcRunStatus` 补充或其他运行监测类型。

## 约束

- IoT 值、孪生规则、状态统计和异常事件不得写入静态对象、模型视图或长生命周期业务缓存。
- 所有缓存读取保持当前项目隔离；缓存空集合是静态权威结果，不作为动态查询回退信号。
- 异步任务使用现有有界执行器；异常必须可观察并向上呈现，不能把失败转换成空列表。必要时加入超时、取消和结构化耗时日志。
- 不引入新的对外接口，不改变 HTTP/SSE 响应字段、事件名称和调度周期。

## 验收标准

- AC1：通行空间同时命中两类规则时结果与旧实现一致；关系过滤不再对每个空间重复遍历全部门禁，调用计数证明关系和规则查询为批量路径。
- AC2：设备统计只查询目标设备和固定动态信息点；三类设备分组及异常、离线、布撤防、运行状态统计与旧实现一致，车库摄像头无实时流协议时仍被排除。
- AC3：修改动态状态或规则后，下一次 HTTP/SSE 查询即可看到新值；静态缓存中不出现动态字段或动态旧值。
- AC4：动态状态与异常事件查询在成功、空结果、部分缺失和异常时均可诊断；异步任务不发生共享容器竞态，异常不会静默返回空结果。
- AC5：聚焦单元测试、调用计数和模块编译通过；性能采样记录批量调用数量、耗时和有界并发行为。

## 非目标

- 不负责设备/空间缓存构建、READY 判定或模型图字段。
- 不负责 dashboard、需求配置结果预计算或其他动态统计子系统。
- 不修改通用 IoT 查询接口、云边实现、批量信息点查询和 Redis 中间态补充逻辑。
- 不改变异常事件风控过滤规则、SSE 调度频率、接口路径和响应契约。
