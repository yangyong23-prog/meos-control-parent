# 安防仪表板与需求配置结果优化

## 目标

减少 `/security/dashboard` 在空间/设备关联和需求配置继承上的重复远程调用，复用静态缓存和需求配置结果预计算；需求配置结果读取与空调需求保持一致，不额外引入就绪状态。

## 范围

- 依赖 `security-static-cache` 提供的设备、空间、建筑楼层和关系读取契约。
- dashboard 的 `ARMING`、`PASSING` 受控空间、关联设备及楼层/建筑关系改为读取静态缓存。
- 将 `ARMING`、`PASSING` 纳入现有 `demand_config_result` 支持集合、刷新和初始化流程。
- dashboard 及安防需求配置调用使用 `listConfigResultsByInstances`，复用空调需求的结果查询契约，不增加独立 READY 状态或实时回退。
- 保留四级继承、空间自身优先、屏蔽空间、黑名单、模板日期和最终配置语义。

## 约束

- `deploymentStatus` 等 IoT 状态仍实时查询，不写入需求结果或静态对象缓存。
- 结果表 miss 按结果查询契约解释为无配置，不根据结果表是否为空推断就绪状态。
- 现有非安防需求类型行为不得改变；支持类型使用统一集合管理，不能在多个入口各自硬编码。

## 验收标准

- [ ] AC1：READY 时 dashboard 不再访问同批 RWD 空间、设备、建筑和楼层静态查询，响应对象集合与旧路径一致。
- [ ] AC2：安防需求结果初始化、配置变更、模板变更、屏蔽/黑名单和空间层级变化可触发正确刷新，项目与模板类型结果范围准确。
- [ ] AC3：已就绪结果与原实时继承结果在 ARMING/PASSING 配置、继承优先级、屏蔽和黑名单语义上逐项一致。
- [ ] AC4：结果 miss、历史日期和动态运行态查询符合现有结果查询契约，不回退实时继承或修改 IoT 实时查询。
- [ ] AC5：聚焦测试覆盖模板类型隔离、空间自定义优先、父级继承、屏蔽/黑名单和回退路径；编译通过。

## 非目标

- 不改造静态缓存的底层表、关系仓储或设备接口模型图字段返回方式。
- 不优化 IoT 状态统计和通行规则聚合。
- 不切换安防以外的需求调用方。
