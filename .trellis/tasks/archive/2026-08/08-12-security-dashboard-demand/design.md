# 仪表板与需求结果设计

## 读取路由

dashboard 入口先确认 SECURITY 静态缓存 READY，再批量读取安防空间、设备、关系以及 `cache_object` 中按 classCode 过滤的通用项目建筑楼层字段；建筑、楼层不建立业务 Key。同一请求不混合缓存与 RWD。动态 `deploymentStatus` 在结果组装阶段实时读取。

建筑和楼层由独立公共项目结构策略构建，不属于 SECURITY 策略。全量构建公共阶段只构建一次；
显式构建支持新版对象模型的一级类型时先构建公共项目结构，失败不得提交该类型 READY。

需求配置入口统一读取 `demand_config_result`，复用空调需求现有结果查询方式，不增加独立 READY 状态，也不使用 SECURITY 静态缓存 READY 作为需求结果开关。结果表 miss 按结果查询契约解释为无配置；需求结果初始化和增量刷新沿用统一支持集合、初始化任务与事件监听器。

## 刷新边界

将 `ARMING`、`PASSING` 加入统一支持集合。配置增删改、模板新增/删除、黑名单/屏蔽变化和空间层级事件复用现有刷新仓储；按实例及下级实例局部重算，模板级变化批量重算。结果内容保持稳定配置，运行态由查询期补充。

## 兼容与回滚

保留旧实时 Gateway 和 dashboard 组装方法作为兼容边界，但本次安防 Dashboard 需求配置固定复用结果查询入口；不以结果表非空推断就绪，不增加 READY 状态，不影响其他需求类型。
