# 缓存模型最终集成与性能验收

## Goal

在不新增业务能力的前提下，完成全链路回归、执行计划、万级对象性能和最终交付边界验收。

## Dependencies

- 父任务：`07-13-cache-object-model-refactor`。
- 前置审核：子任务 01 至 12、14 至 19 已独立通过用户审核；子任务 13 的历史目录保留但数量核验方案已取消，本任务不再依赖其实现交付物。

## Requirements

### 2026-07-18 迁移方案调整

- 当前版本支持的末端、照明不再构建或消费 `cache_rwd_object`、`cache_iot_rule` 等旧版运行结果缓存，只构建新版缓存对象模型。
- 末端、照明消费端在对应一级类型未 READY 时直接查询 RWD 或规则实时数据，不再读取旧版运行结果缓存；READY 后只读取新版缓存，仍不做同请求降级。
- 其他运行监测系统保持现状，不因本次方案调整切换到新版缓存。
- 需要重新审计并调整末端空间设备、末端空间白名单、照明设备、照明首页、模板对象、模板明细和 IOT 规则的构建与读取分支。
- `cache_info_code_template` 继续作为模板过滤元数据持久化，不属于本次停止构建的旧版运行结果缓存。
- 未 READY 的对象和规则实时查询可以沿用实时服务内部既有的 Redis 短缓存；本次停止的是 `cache_rwd_object`、`cache_iot_rule` 等持久化运行结果缓存，不扩大到实时服务内部缓存机制。
- 末端白名单配置只写新版白名单 Key；未 READY 时读取该 Key 的配置对象 ID 后实时查询 RWD，READY 后直接读取新版对象，不再读写旧对象表白名单快照。
- 兼容首版升级：当数据库尚无 `AIR_TERMINAL READY` 且新版白名单 Key 为空时，初始化先读取一次旧对象表；旧白名单 Key 有有效对象 ID 即按历史事实迁移，不受缺失壳配置返回的默认 `FULL` 阻断，并在替换新版 Key 的同一事务内补写 `WHITE_LIST`。无旧 ID 时才按当前壳配置处理；该例外不属于业务消费，数据库 READY 后永久禁止回读旧白名单残留。
- 模型视图字段接口未 READY 时按对象 ID 实时查询 RWD 并返回模型视图字段，READY 后读取新版模型视图表。

- 继承父任务统一异常边界：业务校验和范围冲突使用带中英文资源的 `BusinessException`；JSON 转换统一使用 `ObjectMapperUtils` fail-safe，Converter 不自行捕获 Jackson 异常；写入方在删除前拒绝 `null`，读取方按实际命中结果组装数据，Mapper 和事务异常不得吞掉。
- 云端 READY 启动恢复与边缘 READY 启动/定时收敛任务类统一使用 Nacos 属性 `project.cache.rwd.enabled` 的 `@ConditionalOnProperty`。显式为 `false` 时两个自动任务 Bean 均不注册，因而不会访问权限服务、项目配置、状态数据库或 Redis；属性缺失时默认注册。手动初始化、调试初始化和正常构建写 READY 不受影响，开关变更后云端和边缘端都必须重启生效。
- 覆盖云端新版缓存写入、单类型完整构建、构建锁内数据库 `READY` 提交、云端 Redis 刷新、边缘 READY 收敛和四类读取路由的端到端流程。
- 对末端、照明分别验证对象、模型视图、模板对象明细和 IOT 规则的新版结果与实时结果一致；验证其他运行监测系统始终保持旧链路。
- 覆盖 `allowCache()`、READY/缺失/非法状态、Redis 异常及照明二级类型整体启用的组合回归；历史或测试手工 `FAILED` 只按非 READY 兼容值处理，生产流程不再写入。
- 末端白名单空间只写新版对象模型：配置保存后替换新版白名单 Key，切换全量或删除时只清理新版键关联；`AIR_TERMINAL READY` 后从白名单缓存键读取新对象/模型视图，未 READY 时按该 Key 的配置 ID 实时查询 RWD。
- `/airTerminal/listSpaceEquipment` 的 `AirTerminalSpaceWithStatusQueryParam` 和内部 `RunningMonitorSpaceQueryParam` 均不再接受 `useWhiteList`；服务只按 `SPACE_RANGE_TERMINAL` 决定白名单或项目全量空间范围，缓存构建内部 `useCache=false` 始终计算项目完整空间。
- `POST /cacheRwd/listModelViewFieldsByObjectId` 在末端或照明 READY 后按对象 ID 批量返回模型视图表实际命中的顶层字段；未 READY 时实时查询 RWD，不读取旧缓存。
- `POST /cacheRwd/listAirTerminalControlSpaces` 无请求体，返回当前项目可供白名单配置选择的末端全量管控空间；READY 时读取 `AIR_TERMINAL_listSpace`，未 READY 时实时计算，响应每项只包含 `id`、`localName`、`floorId`、`buildingId`，不受当前白名单模式限制。
- 在云端 Debug 缓存控制器只提供当前集团、当前项目、必填一级类型的初始化入口；只允许末端、照明，并复用单类型完整构建流程，不提供 validate 入口。
- 白名单 READY 请求返回新版表实际查询到的数据，不因部分缺失在同一请求内回退 RWD；未 READY 请求按新版白名单 Key 中的配置 ID 实时查询 RWD。
- 对象模型重建统一按单个新版缓存 Key 执行“事务外计算、短事务替换”；空结果只删除新版键关联，不再删除或写入同 Key 的旧版运行结果缓存，不维护一级类型对象模型上一版快照、对象主表跨 Key 差集或全局孤儿对象清理。无 Key 引用且已经不可达的对象、模型视图和关系记录允许保留，且不得进入按 Key 查询结果；照明关系由每个 Key 按自身替换前后回路 ID 精确删除并重建，多个 Key 命中同一关系时允许重复执行。
- 对象模型写入拆分为对象 Key 替换和通用关系替换两个入口。对象入口接收调用方确定的完整 RWD 对象快照和可选扩展动作，对象与模型视图继续由公共转换器统一投影，调用方不得自行构造两类持久化实体；关系入口只接收一个 `DtpRwdRelationTypeEnum` 和一组以 `id` 表示主体、以 `relObjIds` 表示完整目标的 RWD 对象。写入边界不得查询 RWD 或推断需要维护的关系，调用方已经取得的关系快照必须可以直接提交，不得被公共写服务强制重复查询。
- 取消独立七表数量核验、数量差异报告、手动校验 XXL-JOB 和 `FAILED` 生产写入；`READY` 不再由数量比较决定。
- 使用单项目万级对象、多模板、多缓存键共享对象或规则的基准数据，记录批次数、SQL 长度、查询执行计划、事务时长和内存峰值。
- 主要批量读写不得出现 N+1 或无界单条 SQL；对象、关联、视图、明细和规则查询必须命中设计索引。
- 验证一级类型完整构建成功后在构建锁内提交并刷新 `READY`；READY 后重跑失败保留上一版且状态保持 READY，首次构建失败保持原状态，末端、照明未 READY 时使用实时链路，其他系统继续使用旧链路。
- 运行相关模块编译、单元测试、Mapper/数据库集成测试和关键消费者回归测试，检查云端与边缘端 Flyway 同版本、同内容，以及单个手动初始化 XXL-JOB 的注册和参数语义。
- 汇总向云边同步项目组交付的七表主键和同步字段约束；只验证本项目对边缘数据库 READY 的消费，不实现或验收数据同步链路。
- 集成发现若仅是既有契约实现缺陷，可在本任务修复并记录归属；若需要改变已审核行为，必须退回对应子任务重新评审后再继续。

## Out Of Scope

- 不新增第三个运行监测系统，不引入动态支持范围或灰度能力。
- 不物理删除旧表、旧实体或旧仓储；其他运行监测系统仍可继续使用旧链路。
- 不实现同步表登记、同步协议、同步顺序、边缘数据同步消费或边缘数据完整性核验；边缘端七表 Flyway 由本任务维护。
- 不在本任务重新设计已经逐项审核通过的模型和消费者契约。
