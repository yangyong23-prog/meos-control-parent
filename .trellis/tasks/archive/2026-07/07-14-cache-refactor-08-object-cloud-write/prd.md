# 对象缓存云端重建

## Goal

把对象、缓存键、模型视图和对象关系仓储接入云端增量与全量重建。末端、照明只维护
新版持久化缓存；读取切换由后续任务负责。

## Dependencies

- 父任务：`07-13-cache-object-model-refactor`。
- 前置审核：子任务 01 至 07 已通过。

## Requirements

- 初始化与事件增量重建复用同一对象缓存编排。
- `AIR_TERMINAL`、`LIGHTING` 写入新版对象、视图、Key 关联和通用关系，
  不再写入或删除 `cache_rwd_object` 等旧版运行结果缓存；其他系统保持旧写入链路。
- 调用方在事务外完成 RWD 查询、完整字段准备、关系方向归一化和业务校验。
- 对象 Key 入口只接收当前 Key 的完整 RWD 对象快照，由统一转换器生成对象与模型视图；
  对象、视图、Key 关联和已准备扩展动作在同一短事务中提交。
- 通用关系使用独立入口，只传关系枚举和以 `id/relObjIds` 表达完整主体范围的 RWD 对象。
  同类型正反向结果由调用方先按主体合并。
- 对象公共列、对象 JSON 和模型视图 JSON 分别按最终字段配置投影；
  `monitoringSurveillanceStatus` 以可空单值字符串写入独立列。
- 每个新版 Key 独立替换；空结果只删除当前 Key 关联，不维护一级类型上一版快照，
  不执行跨 Key 差集或对象、视图、无所有权关系的全局孤儿清理。
- 远程查询、转换、业务校验或数据库失败时保留对应写入边界上一版结果并向上抛出。

## Out Of Scope

- 不物理删除旧表或改变其他运行监测系统。
- 不写模板明细或规则，不实现初始化任务、READY 和读取路由。
- 不在公共写服务内查询 RWD 或构造调用方关系范围。

## Acceptance Criteria

- [x] 末端、照明的对象、视图、Key 关联和关系可由增量/全量入口重建，其他系统不变。
- [x] 对象 Key 与关系写入边界独立，调用方不构造持久化实体或资源层关系参数。
- [x] 单 Key 空结果、失败保旧和无全局孤儿扫描语义已落地。
- [x] 对象与模型视图由统一转换器生成，标量状态和两份 JSON 字段配置保持一致。
- [x] 末端、照明不再维护旧版持久化运行结果缓存。
