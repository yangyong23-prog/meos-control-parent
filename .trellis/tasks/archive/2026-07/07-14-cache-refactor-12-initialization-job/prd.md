# 缓存模型手动初始化任务

## Goal

新增只由运维手动触发的云端 XXL-JOB 初始化任务，复用已审核的生产写入能力灌入历史缓存；单个支持类型完整构建成功后，在构建锁释放前直接持久化 `READY` 并刷新云端 Redis。

## Dependencies

- 父任务：`07-13-cache-object-model-refactor`。
- 前置审核：子任务 01 至 11 已通过，直接依赖子任务 08 至 10。

## Requirements

- 继承父任务统一异常边界：业务校验和范围冲突使用带中英文资源的 `BusinessException`；JSON 转换统一使用 `ObjectMapperUtils` fail-safe，Converter 不自行捕获 Jackson 异常；读取方对 `null` 整批降级，写入方在删除前拒绝 `null`，Mapper 和事务异常不得吞掉。
- 只保留初始化任务处理器，任务定义自动注册但不配置自动调度；独立数量核验处理器和手动校验任务已取消。
- 参数支持可选 `groupCodes`、`projectIds`、`runningMonitorTypes`；一级类型仅允许 `AIR_TERMINAL`、`LIGHTING`，不传时默认两者。
- 空集团/项目参数复用现有有效集团、项目遍历和 XXL-JOB 分片能力。
- 执行单元为“集团 + 项目 + 一级类型”；单元失败继续后续范围，最终任一失败则任务失败并输出汇总。失败单元不得修改原数据库或 Redis 状态，也不得写入 `FAILED`。
- 只调用子任务 08 至 10 的公共重建能力，不复制一套初始化专用生成逻辑。
- `AIR_TERMINAL`、`LIGHTING` 的单类型完整构建必须在同一个构建锁内覆盖数据生成、`READY` 持久化和 Redis 刷新，状态完成后才释放锁。
- 一级类型已经 `READY` 后仍允许重跑；成功时幂等保存并刷新 `READY`，失败时保持原状态，各缓存范围失败保留上一版。

## Out Of Scope

- 不执行七表数量比较、差异报告或独立手动校验任务。
- 不写 `FAILED`，不修改边缘 Redis；新旧读取切换仍由既有路由读取云端/边缘 Redis `READY` 决定。
- 不实现自动调度计划。

## Acceptance Criteria

- [x] 支持全量、指定集团、指定项目和指定一级类型执行。
- [x] 单元失败不阻断后续范围，任务结束能正确汇总失败。
- [x] 初始化和增量事件复用同一写入逻辑；单类型完整构建成功后在锁内提交并刷新 `READY`，构建失败不修改状态。
- [x] 独立数量核验任务、`FAILED` 生产写入和 Debug validate 均不存在。
- [x] 本任务 diff 只包含初始化 XXL-JOB、参数和聚焦测试。

## Review Gate

完成实现和质量检查后暂停，等待用户审核初始化参数、构建锁内 READY 时序与失败保留语义；原子任务 13 已因需求变更取消，不再作为后续任务门禁。
